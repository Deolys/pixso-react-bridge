# Частичный перенос и журнал версий

Можно перенести экран, отдельную область или корень микрофронтенда. Область задаётся стабильными Pixso node IDs, а не прямоугольником на снимке. Для реализации берутся выбранные корни и все их потомки, включая скрытые узлы. Если выбран и родитель, и его потомок, пересекающийся выбор сводится к старшему корню.

## Захват выбранного фрагмента

```powershell
pixso-react capture --nodes "12:34" --scope-name "Заказы: микрофронтенд" --config C:/work/app/pixso-react.config.json
pixso-react capture --nodes "12:34,56:78" --scope-name "Два независимых блока" --config C:/work/app/pixso-react.config.json
```

`--nodes` принимает IDs через запятую и переопределяет `pixso.nodeIds` для этой операции. Без переопределения используется конфиг; пустой `pixso.nodeIds` означает весь документ. `scope-name` — человекочитаемая подпись, а не новый идентификатор дизайна или каталог назначения. Для одного микрофронтенда выбирайте его frame/group/instance либо другой отображаемый корень.

Для частичной выборки исходные свойства и координаты документа сохраняются. Цепочки родителей лежат в `capture.scope.ancestors` как контекст: они помогают понять окружение, но не становятся генерируемыми узлами и не расширяют ожидаемое покрытие DOM. Соседние блоки хост-приложения не входят в работу. Разрешённые ссылки и общие ассеты могут сохраняться как ресурсы выбранного фрагмента.

Для чтения больших родителей используются отдельный `context-index.json` и ограниченные части `context/chunks/`. Они не смешиваются с `node-index.json` и узлами реализации. Импорт проверяет соответствие корней, отсутствие дубликатов и целостность цепочки родителей.

Проверка использует собственный viewport выбранного корня и независимый PNG, экспортированный Pixso именно для него при scale=1. Темы, props, router/store и другие провайдеры хоста подключаются через [preview setup проекта](project-data.md). Отдельный `validation.url` может проверить встраивание в хост дополнительно. Самостоятельное совпадение фрагмента не подтверждает всю композицию хоста, неизвестные состояния или поведение на других размерах.

## Выбор из сохранённой версии

```powershell
pixso-react scope --snapshot "D:/design-artifacts/designs/.../versions/..." --nodes "12:34" --scope-name "Карточка заказа" --config C:/work/app/pixso-react.config.json
```

Операция создаёт новую папку версии. Исходная версия и её файлы остаются неизменными. Для каждого выбранного корня уже должен существовать независимый PNG с тем же `nodeId` и scale=1. Если большая версия содержит только reference целого экрана, вырезать из него кусок недостаточно: внешние маски, наложения и фон хоста могли повлиять на изображение. Runtime отклоняет такой выбор с инструкцией повторить `capture --nodes` либо импортировать полный экспорт выбранного узла. Он не выдаёт crop за независимый эталон.

Отсутствующий узел, страница/папка вместо отображаемого корня, потерянный контекст родителей или неполные исходные данные также вызывают ошибку. «Полный перенос» в scoped-запуске означает полноту только явно выбранной области.

Через MCP используйте `pixso_start_job` с `action: "capture"`, `nodeIds`, необязательными `scopeName`, `changeNote`, `previousSnapshot`. Для уже сохранённого снимка — `pixso_scope` с `snapshot`, `nodeIds` и теми же необязательными полями. Читайте фактическую схему установленного runtime; `capture` остаётся фоновой операцией с `jobId`.

## Один короткий журнал на экран

По умолчанию журнал выключен:

```json
{ "versioning": { "screenChangelog": false } }
```

Установите `true` для всех новых версий. Либо явно передайте заметку для одной операции: `--change-note` включает запись и при значении по умолчанию `false`.

```powershell
pixso-react capture --nodes "12:34" --change-note "Добавлены номер заказа и статус оплаты" --previous-snapshot "D:/design-artifacts/designs/.../versions/previous" --config C:/work/app/pixso-react.config.json
pixso-react import --file C:/exports/orders/capture.json --change-note "Обновлена карточка" --config C:/work/app/pixso-react.config.json
```

`scope` принимает те же `--change-note` и `--previous-snapshot`. При включённом журнале для каждого экрана новой версии создаётся ровно один файл:

```text
designs/<file-key>/versions/<time-id>/pages/<page>/screens/<screen>/CHANGELOG.md
```

В нём не более девяти строк: дата UTC, экран, предыдущая версия, количества добавленных/удалённых/изменённых узлов, категории геометрии/оформления/текста/структуры/ресурсов, при необходимости отметка об изменённом PNG и краткая заметка. Категории могут пересекаться; дерево и большие значения не повторяются. Переносы строки заметки сворачиваются, Markdown/HTML экранируются, длина заметки ограничивается.

Сравнение выполняется по стабильным IDs и полным данным узлов; изменения ассетов учитываются по SHA-256. Переезд идентичного ассета в каталог новой версии сам по себе не считается изменением. Если базовая версия не задана, выбирается последняя совместимая сохранённая версия. Совместимость требует того же `fileKey`, набора корней выборки и screen ID. Разные выборки не сравниваются; без подходящего экрана записывается «Начальная версия». Переименование `scope-name` не меняет набор выбранных IDs.

Журнал — необязательная сводка для человека, а не доказательство pixel perfect. Он хранится в новой версии и включается в её контроль целостности; старые журналы не дописываются. Полные данные, хеши и отчёты проверки остаются основными артефактами.
