# Получение данных Pixso без потери контекста

Проверено по официальной документации 16 октября 2026 года. Реального корпоративного файла и доступа к Pixso в среде разработки нет: интеграционные проверки исполняют те же read-only скрипты против детерминированного Plugin API mock. Проверка на вашей версии сервера обязательна командой `inspect` перед первым переносом.

## Поддерживаемые подключения

- **Local MCP**: Streamable HTTP, обычно `http://127.0.0.1:3667/mcp`. Целевой файл открыт и активен в Pixso Desktop либо официальном расширении VS Code. Порт задаётся в конфигурации, он не зашит в клиенте.
- **Новый Remote MCP**: URL вашей организации или `https://pixso.net/mcp`. Для корпоративного развёртывания используйте выданный администратором URL и токен через переменную окружения. OAuth-интерактивный вход этот пакет не реализует.
- **Legacy stdio**: официальный `@pixso/pixso-stdio-mcp` поддерживает `get_node_dsl`, `get_variants`, `get_variable_sets`, `get_variables`, `get_local_styles`; его полный DSL сохраняется, но статус остаётся `unverified`, если нет независимых сведений о полноте. Такое извлечение нельзя передавать в генерацию как полное.
- У прежнего remote интерфейса параметры `file_key`, `guid`; у desktop — `guid`, `simplify` и camelCase. Клиент запрашивает `tools/list` со всеми страницами, сохраняет реальные JSON-схемы и передаёт только поддерживаемые поля. Неизвестный обязательный параметр вызывает явную ошибку.

## Как исключено обрезание

MCP SDK выполняется обычным Node.js процессом. Ответы записываются напрямую в файлы до анализа, а не проходят через лимит вывода инструментов языковой модели. В `raw` сохраняются все поля каждого результата и схема инструментов. В агентский контекст попадают индексируемые части артефактов.

`simplify:true` — сокращённый DSL: `roots` и `refsIndex`, наследование от компонентов, значения по умолчанию и свёрнутые векторы. Его нельзя считать исходным полным файлом. `simplify:false` даёт полное дерево DSL выбранного узла, но не raw Kiwi и не снимок всей модели редактора. Оно сохраняется как дополнительный источник для каждого экрана.

Основной строгий путь использует официальный `eval_script` с фиксированными скриптами только чтения:

1. `pixso.getNodeById` и `findAllAsync` строят независимую полную инвентаризацию: IDs, родитель, порядок дочерних элементов и общее количество. Данные идут страницами по 150 записей; JSON каждой страницы дополнительно передаётся частями с проверкой длины и отпечатка, поэтому даже один узел с десятками тысяч дочерних IDs не раздувает ответ сверх размера части.
2. Для каждого узла считываются документированные свойства и обнаруженные собственные/прототипные свойства. Функции не исполняются; структурные ссылки сохраняются как IDs. Ошибка чтения любого свойства фиксируется и запрещает статус `complete`.
3. JSON каждого узла передаётся частями по 24 000 символов. Один огромный текстовый или векторный узел тоже разбивается, без отбрасывания полей. В каждой части есть длина, смещение и отпечаток полного содержимого; изменение источника или пропущенная часть останавливает проверку. Настройка `chunkChars` допускает меньшие части.
4. Смешанное форматирование текста извлекается через документированные `getRange*` методы. Диапазоны делятся до однородного стиля, соседние одинаковые стили объединяются; полный текст остаётся в `characters`.
5. Разрешаются использованные определения компонентов, стили и переменные, включая alias-цепочки. Определения лежат в `raw/references.json`; использованные стили/переменные также включаются в `raw._resolvedReferences` узлов.
6. Оригинальные изображения выгружаются по `pixso.getImageByHash(...).getBytesAsync()`. Хеш изображения никогда не подставляется вместо GUID узла. Векторы выгружаются в SVG. Для каждого экрана сохраняется reference PNG при масштабе 1 через `node.exportAsync`.
7. Инвентаризация повторяется; каждый узел, определение компонента, стиль и переменная проверяются повторно. Несовпадающие IDs, родители, порядок детей, количество, недостижимые узлы, циклы, исчезнувшие свойства, ассеты или reference PNG дают `incomplete`.

На больших файлах чтение свойств и экспорт параллельны, по умолчанию четыре операции. `pixso.concurrency` позволяет уменьшить нагрузку на корпоративный сервер. Сначала можно явно указать `nodeIds` нужных экранов; без них в область попадают все страницы, включая скрытые и компонентные. Владелец файла должен оставить документ неизменным на время захвата. Публичный API Pixso не даёт транзакционного блокирования документа: проверка начала/конца обнаруживает изменения, но не заменяет immutable revision API.

## Частичный экран и микрофронтенд

В v1.2 `capture --nodes "12:34,56:78" --scope-name "Заказы"` задаёт область одной операции, не меняя постоянный `pixso.nodeIds`. Каждый выбранный корень и все потомки захватываются полностью. Цепочки родителей сохраняются в `capture.scope.ancestors` для чтения контекста; они не включаются в генерируемый хост и проверяемый набор DOM IDs. Координаты исходного документа и raw-свойства сохраняются.

Команда `scope --snapshot DIR --nodes "12:34"` создаёт новую выбранную версию из уже сохранённой. Для неё нужен отдельный PNG выбранного корня, экспортированный в Pixso при scale=1. Снимок целого хоста или его программная обрезка не подтверждают самостоятельный фрагмент. Если отдельного PNG нет, выполните новый прямой `capture --nodes` либо импорт точного экспорта выбранного узла. Папки/страницы не подходят как корень этой команды; выбирайте отображаемый frame/group/instance.

Проверка полного захвата и финальный pixel perfect относятся только к этой области. Подключение к провайдерам и данным хоста задаётся через `validation.setupFile`; сравнение хост-маршрута можно добавить отдельным `validation.url`. [Полный workflow и короткий журнал версий](scopes-and-versions.md).

## Что означает полнота

`complete` означает: выбранная область покрыта всеми доступными через Plugin API узлами и читаемыми свойствами, замкнуты используемые ссылки, сохранены изображения/векторы и reference PNG, проверки согласованности пройдены. Это не обещание доступа к закрытым внутренним данным Pixso, приватным данным сторонних плагинов, исходным шрифтам или исходному Kiwi. Наличие полных исходных данных не доказывает визуальную точность React: для неё нужен отдельный gate Playwright и сравнение с reference PNG.

Любая неизвестная форма ответа, явный сигнал truncation, неразрешённая ссылка либо API-ошибка остаётся видимой в отчёте. Пакет не подменяет отсутствующие значения догадками. Старые серверы без `eval_script` можно обновить или использовать проверенный локальный export bundle через команду импорта. Скрипты не вызывают `apply_design`, setter-методы, создание узлов или изменение файла.
